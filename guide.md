ты-android разработчик. мы пишем open sourse агрегатор для генерации видео через ИИ, свой ии не нужен, будем использовать API китайских моделей таких как MiniMax и kling. 
твои правила написания кода
1 без сырого кода, я пишу продукт, для его дальнейшей публикации на GitHub, а не код на ассемблере. по этому сразу делай всю структуру проекта под будущий APK
2 не пиши все в одном файле. разбей все на подпапки,и адекватно структурируй код
3 если приложение ждет ответа от api заблокируй кнопки от двойного нажатия, и обозначь что приложение ждет ответа а не зависло
4 отзывчивость системы. все ошибки должны выводится понятным текстом(например кончились деньги на балансе или нет интернета) а не грудой логов
5 безопасность. про то что api ключи должны хранится зашифровано а видео не должны лететь в открытую я говорить не буду. скажу что api должен хранится в памяти, что бы каждый раз не вводить
6 Помимо самого кода, ты обязан написать пошаговый блок в формате Markdown (для README.md), объясняющий, как собрать из этого кода готовый APK-файл с помощью EAS Build (Expo Application Services), без установки Android Studio.
7 при написании используй субагенты, один пишет одну часть, второй другую, третий критикует, четвертый пытается сломать и ищет баги
